# RDL流 AIデザイン：目的Bに応じた道具選択

*T4：応用層 / IMPL・OP / DRAFT v0.1*
*依存：RDL_Core / SILN / RDL_中間設計図プロトコル / RDL道具特性*

---

## ■ 0. 一文定義

RDL流AIデザインとは、AIを単一の万能知能として設計するのではなく、**目的Bに応じて、使用する道具・ゲート強度・更新規則・出力形式を切り替える設計思想**である。

---

## ■ 1. 基本原則

AI設計において最初に決めるべきものは、モデルの性能ではなく **目的B** である。

同じ推論能力・同じ生成能力でも、目的Bが異なれば、望ましい挙動は変わる。

```
現実分析B  → 誤接続を避ける
創作B      → 誤接続も物語資源として使う
相談B      → 事実認定より熱源と境界を扱う
教育B      → 失敗過程を見せる
実装B      → 曖昧さをコード化可能な構造へ落とす
```

したがって、AIの道具選択は以下の順で行う。

```
目的Bを設定する
  ↓
許容される誤差の種類を決める
  ↓
必要な道具を選ぶ
  ↓
破壊ゲートの強度を決める
  ↓
出力形式を決める
  ↓
運用中のH / ξを見て更新する
```

---

## ■ 2. 道具選択の基本構造

RDL流では、AIの各機能を「能力」ではなく「道具」として扱う。

| 道具 | 主な用途 | 危険 |
|---|---|---|
| 統計モデル / FEP系 | 集団Bの安定傾向を読む | 個体差を吸収しすぎる |
| LLM | 曖昧なFから仮説M_Bを生成する | 過剰接続・もっともらしい誤読 |
| RAG / 検索 | 外部記録によるF補強 | 検索対象Bに依存する |
| 構造破壊ゲート | M_Bの耐久検査 | 強すぎると創造性が落ちる |
| シミュレーション | 仮説M_Bの動態を見る | 初期Bが悪いと誤った世界が安定する |
| エージェント化 | M_Bを行動に接続する | 誤ったM_Bが現実を変えてしまう |
| 翻訳接続系 | 外部理論をRDLへ接続する | 借用元の前提を密輸する |

重要なのは、道具そのものに善悪を置かないこと。

```
道具の評価 = 目的B × 使用文脈 × ゲート強度 × 破断条件
```

---

## ■ 3. 目的B別のAI設計

### 3.1 現実分析B

目的：現実の構造をなるべく誤読せずに読む。

推奨道具：

- 検索 / RAG
- 統計データ
- 構造破壊ゲート
- 代替M_B生成
- 反証条件チェック

ゲート強度：強

禁止または制限：

- 弱いW_ijの過剰接続
- 意図過剰仮説
- 反証不能な隠れM_B
- 「全部つながっている」型の閉鎖構造

基本出力：

```
現時点で言えること
不明なこと
代替説明
破断条件
次に見るべきF
```

---

### 3.2 相談・対人理解B

目的：相手や自分のH / ξ / Bのズレを扱う。

推奨道具：

- SILN分解
- 感情・違和感のH源泉検査
- 個人Bと集団Bの分離
- 反応パターンのM_B化
- 言い換え・再境界化

ゲート強度：中〜強

注意：

相談Bでは、事実認定を急ぎすぎない。

```
何が起きたか
```

よりも先に、

```
どのBで痛みが発生しているか
どのM_Bが守られようとしているか
どのHが蓄積しているか
```

を見る。

ただし、現実の他者を確定診断する方向には行かない。

---

### 3.3 創作B

目的：物語・世界観・キャラクター・都市・制度の生成。

推奨道具：

- 低〜中ゲートの仮説生成
- 陰謀論生成
- 噂生成
- NPCごとのB生成癖
- シミュレーション
- 破綻を物語イベントとして扱う設計

ゲート強度：弱〜中

創作Bでは、現実分析では危険な過剰接続も資源になる。

```
誤読
噂
偏見
妄想
不完全な説明
局所的に整合する陰謀論
```

これらはNPCや社会の生命感を作る。

ただし、現実誘導ではなく、作品内Bとして閉じる必要がある。

---

### 3.4 教育B

目的：構造を見る力と、構造を疑う力を育てる。

推奨道具：

- あえて弱いM_Bを作る
- その後に破壊ゲートへ通す
- W_ij検査
- 代替説明比較
- 失敗例の可視化

ゲート強度：段階可変

教育Bでは、最初から正解だけを出すより、

```
なぜその誤読が魅力的に見えるのか
どこで過剰接続が起きたのか
どのFが足りなかったのか
どのBが強すぎたのか
```

を見せる方が有効である。

---

### 3.5 実装・AIコーディングB

目的：曖昧な意図を、コード化可能な構造へ落とす。

推奨道具：

- RDL中間設計図
- UML / 状態遷移図 / データ構造
- 禁止補完リスト
- 可換性テスト
- 破断条件
- テストケース生成

ゲート強度：強

実装Bでは、曖昧さを創造資源として放置しすぎるとバグになる。

したがって、以下を明示する。

```
入力
出力
状態
境界B
依存W_ij
禁止補完
失敗条件
更新条件
```

## ■ 4. ゲート強度の設計

AIの個性や用途は、構造破壊ゲートの強度で大きく変わる。

| ゲート強度 | 特徴 | 向く用途 | 危険 |
|---|---|---|---|
| 強 | 誤接続を拒む | 現実分析 / 実装 / 医療・法律補助 | 創造性が落ちる |
| 中 | 仮説と検査を両立 | 相談 / 教育 / 設計 | 判断が遅くなる |
| 弱 | 多くの接続を許す | 創作 / NPC / 発想支援 | 陰謀論化・誤読 |
| 意図的破損 | 偏ったM_Bを生成 | キャラ造形 / 敵対NPC / カルト描写 | 現実応用不可 |

RDL流では、ゲートを一律に強くしない。

```
目的Bに対して必要な強度にする
```

これが原則である。

## ■ 5. FEP / 統計データの位置づけ

FEPや統計データは、RDL流AIデザインにおいて有力な初期値である。

```
FEP / 統計モデル
= 集団Bにおける安定傾向の抽出器
= 個体Bを読むための初期事前分布
= ただし最終判定ではない
```

運用手順：

```
集団統計を初期M_Bとして借りる
  ↓
個体のFを見る
  ↓
差分をEとして扱う
  ↓
Eが蓄積すればHと見る
  ↓
Hが大きければ個体Bを再仮設する
```

個体差を統計に吸収しすぎないことが重要である。

---

## ■ 6. 陰謀論生成の扱い

陰謀論生成は、現実分析Bでは危険だが、創作BやNPC設計Bでは有用である。

### 現実分析B

```
陰謀論生成 = 低ゲートの過剰M_B生成
```

対策：

- 反証条件を要求する
- 代替M_Bを比較する
- 意図過剰を検査する
- W_ijを相関・因果・連想に分ける
- 反証を隠蔽として吸収していないか見る

### 創作B / NPC設計B

```
陰謀論生成 = NPCのH処理・世界解釈・行動駆動
```

用途：

- 噂の生成
- 派閥対立
- 誤解による事件
- カルト化
- 自己成就的予言
- プレイヤーへの不完全情報提示

同じ機能でも、目的Bによって危険物にも資源にもなる。

---

## ■ 7. RDL流AIの最小設計式

RDL流AIは、以下のように設計できる。

```
AI = 目的B選択器
   + M_B生成器
   + F観測器
   + E/H検出器
   + 構造破壊ゲート
   + B再仮設器
   + 出力形式変換器
```

通常のAI設計では、モデルの性能や精度が中心になりやすい。

RDL流では、

```
何のために読むのか
どのBで読むのか
どの誤差を許すのか
どこで壊すのか
いつ更新するのか
```

を中心に置く。

---

## ■ 8. 結論

RDL流AIデザインの核心は、AIに一つの正しい振る舞いを求めないことにある。

```
現実分析では疑い深く
相談では熱源に敏感に
創作では過剰接続を許し
教育では誤読過程を見せ
実装では曖昧さを潰す
```

つまり、

> **目的Bに応じて、使う道具・ゲート強度・更新規則を変える。**

これがRDL流AIデザインである。
